# Deployment

Two things can be hosted, independently:

| Piece | Where | Needed for |
| Static storefront (`client/dist`) | GitHub Pages (already live) | Browsing, menu, WhatsApp booking |
| API (`server`) + MongoDB | Render (blueprint in `render.yaml`) or any Node host | `/admin`, analytics, live catalogue edits |

## 1 — GitHub Pages (the live preview)

`.github/workflows/deploy-pages.yml` builds the client on every push to `main` and publishes it.

`VITE_BASE` is set to `/<repo>/` so asset URLs and the router base both work on a project site. The
build ships `client/public/demo/catalogue.json` because Pages cannot run the API:

```shell
npm run demo:snapshot     # rebuild it after changing the seed menu
git add client/public/demo/catalogue.json && git commit -m "Refresh menu snapshot"
```

Repository variables (Settings → Secrets and variables → Actions → Variables), all optional:

| Variable | Effect |
| `VITE_API_URL` | Full API origin including `/api`. Leave unset on Pages. |
| `VITE_DEMO_CATALOGUE` | `true` (default) serves the committed snapshot; `false` talks to the API. |
| `VITE_PUBLIC_SITE_URL` | Canonical/OG URLs. |

SPA deep links work because the workflow copies `index.html` to `404.html`.

## 2 — API on Render

1. MongoDB Atlas → create a free cluster, a database user, and allow Render's egress
   (`0.0.0.0/0` is fine for the free tier). Copy the connection string.
2. Render → **New + → Blueprint** → pick this repository. It provisions:
   * `uv-clinics-api` — the Express service (health check `/api/health`).
   * `uv-clinics-web` — an optional static service; not needed if you use Pages.
3. Fill the `sync: false` values on the API service: `MONGODB_URI`, `CORS_ORIGINS`
   (e.g. `https://zeeshanshaikh95.github.io`), `PUBLIC_SITE_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`.
   `JWT_SECRET` is generated by Render. `AUTO_SEED=true` creates the first admin and default settings
   on boot — it never writes catalogue data.
4. Open `https://<api>.onrender.com/api/health` and confirm it answers.
5. Set the Pages repository variable `VITE_API_URL=https://<api>.onrender.com/api` and
   `VITE_DEMO_CATALOGUE=false`, then re-run the Pages workflow.
6. Sign in at `https://zeeshanshaikh95.github.io/uv-clinics/admin`, change the bootstrap
   password, then add the menu.

Free tier: a Render web service sleeps after ~15 minutes idle; the first request afterwards takes
~30 s. Static Pages reads are unaffected.

## 3 — Uploads

Images uploaded in Admin are written to `server/uploads` and served from `/uploads`. Render's disk is
ephemeral, so uploaded files disappear on redeploy. For real use, either:

* keep images in `client/public/images` and paste their paths in the admin form, or
* swap the Multer disk storage in `server/src/middleware/upload.ts` for Cloudinary/S3.

The seed menu and the Pages snapshot reference `/images/...` paths, which ship with the client build
and are therefore permanent.

## 4 — Checks before going live

```shell
npm run typecheck
npm run build
npm run demo:snapshot     # only if the seed menu changed
```

Then load the deployed site and confirm: the hero slider advances, a service page opens, “Add to your
list” works, the WhatsApp button opens a pre-filled chat, and `/admin` asks for credentials.
